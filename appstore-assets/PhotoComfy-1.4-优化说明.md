# PhotoComfy 1.4 优化说明

## 版本信息

- 应用名称：PhotoComfy
- 当前版本：1.4（`CFBundleShortVersionString`；仓库根 `Cargo.toml` 按 Cargo 要求写作 `1.4.0`）
- App Store Connect 构建号：11
- 发布方式：只上传 App Store Connect 供 TestFlight 内测；本版本未创建 Git tag 和 GitHub Release，未提交审核
- Bundle ID：`photoComfy`
- 支持设备：iPhone、iPad
- 对照版本：1.3

## 1. 字体菜单里能直接找到中文字体

- 修复 1.2、1.3 的问题：中文字体包已经编进应用（19 个家族），但字体菜单里它们只以英文族名
  （`Noto Sans SC`、`Smiley Sans`、`LXGW WenKai Lite`……）混在几十个其他语种的字体里，旁边只有 `AaBbCc` 样张，
  看上去就像“只有英文字体”。
- 中文界面下，字体菜单现在：
  - 打开即在顶部列出“中文字体”分组，排在最近使用的字体之后；日文、韩文界面同理（“日本語フォント”“한글 글꼴”）。
  - 分组里的字体用中文名显示：思源黑体、思源宋体、霞鹜文楷 轻便版、得意黑、霞鹜新晰黑＋、抖音美好体、朱雀仿宋、
    悠哉字体、寒蝉圆黑体、马善政毛笔楷书、站酷快乐体、站酷庆科黄油体、站酷小薇体、有字库龙藏体、钟齐志莽行书、
    钟齐流江毛笔草体、霞鹜漫黑，以及繁体对应的“思源黑体 繁体”“思源宋体 繁体”。
  - 每个能显示中文的字体，样张栏在 `AaBbCc` 旁显示“中文字体”样张。
  - 可以用中文名搜索：输入“得意黑”或“霞鹜文楷”就能找到对应字体。
- 名字的来源：优先取字体自己 `name` 表里该语言的记录；字体没有这种记录时（Noto Sans SC、Ma Shan Zheng、
  ZCOOL KuaiLe 等），取字体包清单里登记的名字。
- 分组和样张由界面语言决定，与平台无关：英文等非中日韩界面下，字体菜单与之前完全一样。
- 文档里保存的仍是英文族名；分组里的字体在下方字母顺序表里保留原来的位置。

## 2. 构建修正

- Xcode 的 Cargo 构建阶段改为每次构建都运行。之前它只在清单里的少数输入文件变化时才运行，
  只改共享代码（`crates/`）时会被跳过，App 里只剩 Xcode 的空二进制。

## 已完成的验证

- `photocraft-text`：按界面语言取字体名（清单与 `name` 表）的测试通过（嵌入字体包时）。
- `photocraft-ui-egui`：字体菜单（分组顺序、中文名、中文名搜索、中文界面下的菜单本身）、样张、手指点选字体行等
  受影响测试 358 项通过（嵌入字体包和 craft-fonts 时）；Clippy 与格式检查干净。
- iOS 27.0 模拟器（iPad Pro 11 英寸，无 AIGC Release 构建，XCUITest 真实点击）：
  - 字体菜单打开即显示“中文字体”分组，组内为中文名和中文样张。
  - 点选“得意黑”后新建文字并输入中文，文字以得意黑显示；点选“思源宋体”后同样正常（常规字重）。
  - 用中文名搜索可用（“霞鹜文楷”找到 LXGW WenKai Lite）。
  - 中文输入通过系统键盘正常进入画布文字图层。
- 无 AIGC 归档与 App Store Connect 上传结果见本次交付记录。

未验证：真机上的实际触控（Apple Pencil 与手指）；iPhone 上未逐项点开字体菜单（菜单代码与 iPad 共用）；
Android 构建（分组与样张的代码同样编入 Android，未运行）。另有 3 项上游既有的字体提交测试
（`selected_fonts_commit_pattern_0/2/3`）在本机一直失败，与本次改动无关。

## 面向用户的简短更新说明

字体菜单新增“中文字体”分组，思源黑体、思源宋体、霞鹜文楷、得意黑等 19 款中文字体以中文名直接列出并带中文样张，
也可以用中文名搜索。
